# DEMO — 3 минуты, полностью офлайн (mock-режим)

Сценарий для выступающего. Всё работает без сети и без Active Directory; подписи кнопок — как на экране.

## Подготовка (до выхода на сцену, ~2 минуты)

```bash
cd frontend && npm run build                  # один раз: UI будет раздаваться самим бэкендом
cd ../backend
rm -f data/risk_radar.db*                     # чистая БД → при старте засеется «история» из 5 сканов
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

В PowerShell вместо `rm -f`: `Remove-Item data\risk_radar.db* -ErrorAction SilentlyContinue`.

Откройте **http://127.0.0.1:8000** в полноэкранном браузере (F11). Можно включить режим «в самолёте».
Если нужен сброс посреди репетиций — остановите сервер, удалите `data/risk_radar.db*`, запустите снова.

## Если спросят

- **Как считается 85?** `score = min(100, round(100·(1 − Π(1 − wᵢ))·k))`, веса в YAML-правилах, k = 1.2 для Tier-0. ServiceAccount01 входит в Backup Operators (операторская группа, не Tier-0), поэтому k = 1.0 → ровно 85. Тест `test_risk_engine.py` это проверяет.
- **Какие права нужны?** Обычный Domain Users; Event Log Readers — только для spray/brute-force. Domain Admin не нужен.
- **Почему не проверяете слабые пароли по хэшам (DSInternals)?** Для этого нужны права репликации — это нарушает принцип минимальных привилегий. Используем косвенные признаки: политика, флаги UAC, события 4625/4771/4740.
- **Русская локаль DC?** Группы ищутся по SID/RID, а не по имени — «Администраторы домена» находятся так же (есть тест).
- **Реальный AD?** `SOURCE=ldap` + параметры в `.env`; `scripts/seed_lab_ad.ps1` создаёт такой же лабораторный домен. Переключатель **Mock / Live LDAP** в верхней панели.
- **Как сравнить с прошлым сканом?** Блок *Since last scan* и `GET /api/scans/{id}/diff` — новые, исправленные и ухудшившиеся находки.
